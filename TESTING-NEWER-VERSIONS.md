# Testing on the customer's stack (Expo SDK 55 / RN 0.83 / Gradle 9)

This app has been moved onto the same toolchain a customer reported failures on, so the
three SDK bugs we fixed can be reproduced and verified here instead of in their project.

## What changed

| | Before (SDK 52) | Now (SDK 55) |
|---|---|---|
| Expo | `^52.0.0` | `~55.0.28` |
| React Native | `0.76.9` | `0.83.10` |
| React | `18.3.1` | `19.2.0` |
| Gradle | `8.10.2` | `9.0.0` |
| AGP | (from RN 0.76) | `8.12.0` (from RN 0.83) |
| Kotlin | `1.9.25` | `2.1.20` |
| compileSdk / targetSdk | 35 / 34 | 36 / 36 |
| NDK | `26.1.10909125` | `27.1.12297006` |
| Architecture | New Arch (opt-in flag) | New Arch (mandatory) |

Version numbers come from Expo SDK 55's own `bundledNativeModules.json` and RN 0.83.10's
`gradle/libs.versions.toml`, not guesswork.

Other notable edits:

- **`newArchEnabled` removed from `app.json`** — SDK 55 dropped the Legacy Architecture,
  so the flag no longer exists. (`android/gradle.properties` still carries it, which is
  what the SDK 55 template does.)
- **`react-native-worklets@0.7.4` added** — Reanimated 4 requires it as a peer.
  Reanimated went `3.16` → `4.2.1` in this SDK jump.
- **`react-test-renderer` / `@types/react-test-renderer` removed** — no longer a
  `jest-expo` peer under React 19.
- **`patches/expo-constants+17.0.8.patch` deleted.** It contained nothing but
  accidentally-committed Gradle cache and Eclipse metadata (`.gradle/8.9/*.lock`,
  `.project`, `bin/`) — no real code. Pinned to expo-constants 17.0.8, it would have
  hard-failed `npm install` on SDK 55.
- **`patch-package` kept, now with a real patch** — see the next section.

# Patching the npm SDK (`patches/@couchbase+…+1.1.0.patch`)

This app installs the SDK from npm, and published **1.1.0 does not yet contain our
fixes** — two of which are hard build blockers on this stack. So `postinstall` runs
`patch-package`, which applies `patches/@couchbase+couchbase-lite-react-native+1.1.0.patch`
automatically after every `npm install`.

### What the patch changes, and why each one matters here

| Fix | File | Needed on this stack? |
|---|---|---|
| AGP pin `8.0.0` → configurable (default 8.12.0) | `android/build.gradle`, `android/gradle.properties` | **Blocking.** Gradle 9 rejects AGP 8.0.x. |
| `Map<String, Any>` → `Map<String, Any?>` | `CblLoggingModule.kt`, `LogSinksManager.kt` | **Blocking.** Kotlin 2.1.20 fails `compileDebugKotlin`. |
| `__has_include` guard for the Swift header | `ios/RCTCblModules.mm` | Only when `use_frameworks!` is on — included so the iOS repro works. |

**Deliberately not patched:** the `allprojects { }` removal from the library's
`android/build.gradle`. In a subproject build script, `allprojects` covers only that
project and its (nonexistent) children, so while the module is autolinked it is
harmless. It only caused `It is too late to set namespace` when a root
`apply from:` pulled it into the app's root project — which this app no longer does.
Keeping the patch minimal reduces the chance of conflicts. Say the word if you'd rather
`node_modules` mirror the fixed SDK exactly.

### When 1.1.1 ships — delete the patch

The version is encoded in the filename on purpose. Once the fixes are published:

```bash
rm patches/@couchbase+couchbase-lite-react-native+1.1.0.patch
# bump the dependency to ^1.1.1 in package.json, then
npm install
```

If you bump the SDK and forget, patch-package fails or warns loudly rather than
silently mis-patching — it will not quietly do the wrong thing.

### Patch vs. `sync-cbl` — use which?

- **`patches/`** → testing against the **published** SDK. Committed, automatic, works
  for anyone who clones this repo.
- **`npm run sync-cbl`** → iterating on your **local** SDK checkout, before publishing.
  Requires the checkout; overwritten by `npm install`.

## Upgrade steps

The `android/` and `ios/` folders are generated by prebuild. A jump this large needs them
regenerated — hand-edits alone are not enough.

```bash
cd expo-cbl-travel

rm -rf node_modules package-lock.json
npm install

# Regenerate native projects from the SDK 55 templates
npm run prebuild:clean

# Sanity-check the dependency graph
npx expo-doctor

# Build
npm run ios
npm run android
```

## Reproducing the customer's iOS failure

The `use_frameworks!` header bug only appears under framework linkage, which is **off** by
default. To turn it on, add to `ios/Podfile.properties.json`:

```json
"ios.useFrameworks": "dynamic"
```

then `npx pod-install ios`. On an unfixed SDK this fails with
`'cbl_reactnative-Swift.h' file not found`; with the `__has_include` guard it compiles.

> To make this permanent across `prebuild --clean`, set the same property from
> `plugin.config.js` via `withPodfileProperties`.

## Reproducing the customer's Android failures

Gradle 9 is now in use, so the strict checks that caught the other two bugs are active:

- **`It is too late to set namespace`** — needs a module that sets its own namespace.
  Add `@react-native-firebase/analytics` to see it. It only triggers when the root
  project pulls in the library's `allprojects { }` block, which is fixed both in the SDK
  and in this app's `plugin.config.js`.
- **`Initializer type mismatch` in `CblLoggingModule.kt`** — Kotlin 2.1.20 is strict about
  `HashMap<String, Any?>` vs `Map<String, Any>`. Fixed in the SDK.

# Syncing local SDK changes into `node_modules`

`scripts/sync-cbl-sdk.js` copies your local `cbl-reactnative` checkout into this app's
`node_modules`, so you can test unpublished fixes without publishing to npm.

```bash
npm run sync-cbl              # sync (auto-detects the SDK checkout)
npm run sync-cbl:check        # report what differs, write nothing
node scripts/sync-cbl-sdk.js --src=/path/to/cbl-reactnative
node scripts/sync-cbl-sdk.js --clean       # also wipe stale Gradle/Xcode caches
node scripts/sync-cbl-sdk.js --dry-run --verbose
CBL_SDK_PATH=/path/to/cbl-reactnative npm run sync-cbl
```

**How the SDK is found**, in order: `--src=`, then `$CBL_SDK_PATH`, then
`../cbl-reactnative`, `../couchbase-lite-react-native`, `~/Desktop/cbl-reactnative`,
`~/projects/cbl-reactnative`.

**What it copies:** exactly the paths `npm publish` would ship — `src`, `lib`, `android`,
`ios`, `cblite-js-common/{cbl-js-swift,cbl-js-kotlin}`, `app.plugin.js`, the podspec and
`package.json`. Build outputs, `node_modules`, tests, dotfiles and the Gradle wrapper are
skipped, so `node_modules` ends up matching a real install.

It compares file contents, so it only reports genuine changes and is safe to re-run
(a second run reports "Already in sync").

### Gotchas it warns you about

- **JS/TS changes need an SDK build first.** The app loads the SDK's compiled `lib/`, not
  `src/`. If `src/` is newer than `lib/`, the script warns you — run `npm run prepare` in
  the SDK repo before syncing.
- **Native changes need a real rebuild**, not a Metro reload:
  `npx pod-install ios && npm run ios`, or `npm run android`. Use `--clean` if Gradle or
  Xcode seems to be reusing stale objects.
- **`npm install` overwrites `node_modules`** — re-run `npm run sync-cbl` afterwards.
